既定値を「静かなほう」へ寄せ、型はあるのに効いていなかった `BentoGrid` の `span` を実装した。**素で置いたときの見た目が変わるため、0.x の慣例に従って minor に載せる。**

## 既定値の変更（利用者の画面が黙って変わる）

- **`Badge` / `Tag` / `Chip` の既定 `intent` が `primary` → `neutral`**（T250 ①・#615）。指標は「目立たせるために置く」ものではなく「状態を言う」ものなので、既定が着色されていると**意味の無い強調が画面中に散る**。強調したい箇所では `intent="primary"` を明示する
- **`Card` / `Stats` の既定 `variant` が `elevated` → `outline`**（T250 ②・#617）。実測では `<Card>` 89 箇所のうち `variant` を明示しているのは 21 箇所で、残りはすべて既定の影に乗っていた。影は「面が浮いている」ことを意味する語彙なので、既定は枠線にする。影が要る箇所では `variant="elevated"` を明示する

## 効いていなかった prop が効くようになる

- **`BentoGrid.Item` の `span` / `rowSpan`**（T249・#616）。型は `span?: 1 | 2 | 3` を受け取るのに、**定義する CSS が 1 行も無いまま 8 箇所から渡されていた**。`classNames` は解決しない文字列をそのまま出すので DOM にはクラスが載り、型も lint も VRT も鳴らなかった。今回 CSS を実装したので、**`span` を渡していたタイルは実際に複数カラムを占める**

## 描画が変わらないもの

- `BentoGrid` の header にあった `primary` の斜めグラデーションを、サーフェス階層のトークン（`surface-subtle`）に置き換えた（T248・#612）。部品の既定に入っていたため、`BentoGrid` を素で置いた画面すべてに出ていた
- `Audio` の `135deg` グラデーションを単色へ畳んだ（T248・#612）。2 つの停止点が同じトークン（`surface-inverse`）を指しており、**絵としては元から単色**だったので 1 画素も変わらない
- `Skeleton` の wave から `will-change: transform` を外した（T258 ⓐ・#627）。VRT が同じコミットで撮り直すと再現しなかった原因で、描画そのものは変わらない

## 利用者への影響

**コードを変えなくても見た目が変わる。** 既定のまま使っている場合:

| 部品 | これまで | これから | 戻し方 |
| --- | --- | --- | --- |
| `Badge` / `Tag` / `Chip` | primary の色が付く | 無彩色（`neutral`） | `intent="primary"` を明示 |
| `Card` / `Stats` | 影で浮く（`elevated`） | 枠線（`outline`） | `variant="elevated"` を明示 |
| `BentoGrid.Item` | `span` は無視されていた | `span` / `rowSpan` が効く | 渡していた値を見直す |
