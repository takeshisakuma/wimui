チャートの**軸の目盛り**と**凡例のラベル**の文字色を、非テキスト用に設計された色からテキスト用トークンに変えた。

どちらも「非テキスト用の色を文字に使っている」という同じ形だった。

**軸の目盛り**: recharts は目盛りラベルを `fill: stroke` で描くため、軸線のための色（`--wim-color-text-disabled` ＝**無効状態のための色**）がそのまま文字色になっていた。実測は light 3.45 / dark 3.34（通常テキストに必要なのは 4.5）。

**凡例のラベル**: recharts の `<Legend>` は既定でラベルの文字色に**系列色**を使う。系列パレットは「細いマークが見分けられること」＝ 3:1 を前提に設計してあるので、文字に使うと構造的に 4.5 へ届かない（light の secondary で 2.02）。色を選び直しても解けない（3:1 を満たす彩度のある色はたいてい 4.5 を割る）ため、**文字色だけを `--wim-color-text-secondary` に寄せ、色による系列の識別は凡例のスウォッチに任せる**ようにした。

**軸線・グリッド線・系列の色は変えていない。** 線は非テキスト（WCAG 1.4.11 の 3:1）で、そちらは足りているため。

`AreaChart` / `BarChart` / `LineChart` / `PieChart` / `RadarChart` / `ScatterChart` / `Heatmap` の見た目が変わる ── **目盛りと凡例の文字が濃くなる**。公開 API に変更は無い。

実測: 凍結してある `color-contrast` の incomplete を実ブラウザで測り直したところ、この変更前は 512 ノード中 365 件が 4.5 を割っていた（軸の目盛り 300 件・凡例のラベル 65 件）。変更後は 0 件。
