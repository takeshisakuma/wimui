# Tokenization Exceptions (トークン化除外ルール)

WIM UI では、保守性と一貫性を高めるためにデザイントークンへの移行を推進していますが、以下のケースについては、「意図的なハードコード」としてデザイントークンの適用を免除しています。

これらを無理にトークン化（抽象化）すると、コンポーネントの視覚的整合性が失われたり、メンテナンス性が低下したりする恐れがあるためです。

---

## 1. 幾何学的整合性 (Geometric Harmony)
コンポーネント内部のパーツ同士が数学的な比率や特定の形状（正方形・真円・特定アスペクト比）を維持するために必要な値。

- 理由: トークンスケール（例: 4px刻み）に無理に当てはめると、パーツ同士が重なったり、意図したアスペクト比が崩れたりするため。
- 具体例:
  - `HamburgerMenu`: バーの厚み（2px）・間隔（6px）・border-radius（4px）— バー間比率と全体高さの幾何学的整合性。
  - `RangeSlider`: トラック高さ（6px）・サム直径（18px）— サムがトラックの3倍径になる比率。ヒット領域（24px）はサムを確実にカバーする最小タッチ領域。
  - `Loader (bars)`: 各サイズのバー寸法（sm: 3×12px、md: 4×16px、lg: 8×32px）— 幅:高さ = 1:4 の比率を維持。
  - `Loader (dots)`: 各サイズのドット直径（sm: 4px、md: 8px、lg: 16px）— sm を基準とした倍増スケール。
  - `ChatUI`: 吹き出し矢印の `border-width`（6px 系）と配置オフセット（`top: 10px` / `±6px` / `calc(50% - 6px)`）— CSS border-trick による三角形描画と、矢印寸法（6px）に連動する配置は px 固定が必須。
  - `ChatUI`: タイピングドットの直径（6px × 6px）— typing バブル高さ（24px）に対する比率を維持するドット寸法。
  - `Cascader / TreeSelect`: スクロールバー `border-radius: 3px`（スクロールバー幅6pxの半分 = 真円）。
  - `Splitter`: ハンドルの負マージン（-4px = ハンドル幅8pxの半分）— パネルとのオーバーラップ量の幾何学的計算値。
  - `Alert / Banner`: アイコンの `svg` 寸法（Alert: 18px、Banner: 16px）— ボタン領域に対する適正比率。
  - `TreeView`: スペーサー寸法（24px × 24px）— 展開ボタンと完全一致させるインデント用スペーサー。
  - `AgentStatus`: ステータスドット直径（sm: 6px / md: 8px / lg: 10px）— サイズ段階の比率スケール。
  - `Lightbox` / `FloatButton`: 操作ボタン・バッジ内の正方形アイコン／ドット寸法。
  - `Video`: 音量サム直径（12px）— トラック高さに対する比率。
  - `List`: bordered disc の `top: calc(padding-y + 0.55em)` — 1 行目の光学中心。

## 2. 描画補正 (Browser Rendering Fixes)
ブラウザのレンダリング（アンチエイリアシング、サブピクセルレンダリング）による微妙なボケやズレを解消するための微細な値。

- 理由: これらは「デザイン上の意味」ではなく「実装上の技術的補正」であるため。
- 具体例:
  - `margin-top: -1.5px;` (垂直方向の中央揃えの微調整)
  - `box-shadow: 0 0 1px ...` (ボーダーのジャギー防止)
  - `Video / Audio`: プログレスバーの `border-radius: 2px`（高さ4pxのバーにおけるサブピクセルレンダリング補正）。
  - `Lightbox` カウンタの `text-shadow`、`Video` つまみのソフトハロー — 暗いオーバーレイ上の可読性。

## 3. 構造上の固定寸法 (Structural Logic)
特定のレイアウトにおいて、コンテンツの最小限の視認性や操作性を担保するために、他との兼ね合いを無視してでも死守すべき寸法。

- 理由: グローバルな間隔設定（Spacing）に依存させると、将来的にグローバルの余白を変更した際に、特定の複雑なレイアウトが壊れる（オーバーフローする等）のを防ぐため。
- 具体例:
  - `Kanban`: 列の固定幅（280px）。
  - `Splitter`: ハンドルの当たり判定幅・高さ（8px）。
  - `Icon`: `width: 1em; height: 1em` — `font-size` に追従させる相対的な構造寸法。トークン化すると親の font-size 継承が壊れる。
  - `OtpInput`: セルの固定寸法（3rem × 3rem）— タップ操作・視認性を担保する最小セルサイズ。
  - `Audio / Video`: プログレスバーの高さ（4px）— UI クロムとして視認可能な最小高さ。
  - `Alert`: 閉じるボタン領域（28px × 28px）— WCAG 2.5.5 のタッチターゲット要件への準拠。
  - `Banner`: 閉じるボタン領域（24px × 24px）— コンパクトなバナー内での最小タッチ領域。
  - `TreeView`: ネイティブ checkbox の寸法（16px × 16px）— ブラウザのデフォルト操作サイズ。
  - `Cascader / TreeSelect`: スクロールバー幅（6px）— スクロールバーの最小視認幅。
  - `Lightbox`: ヘッダー操作（40px）／ナビ（56px・狭幅 44px）のタッチターゲット。
  - `GanttChart`: タスク名列幅（160px / 狭幅 100px）とタイムラインスクロールバー（8px）。
  - `RichTextEditor`: セマンティック幅段階・ツールバー chrome 寸法。
  - `FloatButton`: 展開ラベル `max-width: 200px`。
  - `Markdown` / `StreamingText` / `MarkdownRenderer`: `ul` / `ol`（Renderer は `.list`）の `padding-inline-start: 1.5em` — outside マーカーは font-size に追従する溝が要る。`spacing-xl`（12px）では本文より左へはみ出す。
  - `List`: bordered / hoverable の disc `0.35em` — マーカーは font-size に追従する。
  - `Video`: 音量スライダー展開幅・設定メニュー位置／最小幅／最大高さ。

## 4. インタラクションの物理挙動 (Interaction Physics)
ホバー時やアクティブ時の「感覚的なフィードバック」に使用される数値。

- 理由: セマンティック（意味論的）な値ではなく、アニメーションの「味覚」に近い性質を持つため。ただし、色の変化については `oklch` 相対色構文を用いるのが標準であり、本例外は `scale` や `translate` などの物理的な変形を指します。
- 具体例:
  - `transform: scale(0.98);` (クリック時の沈み込み)
  - `transform: translateY(var(--wim-lift-sm));` (ホバー時の浮き上がり)

## 運用ルール (Governance)

「例外」が将来的な技術負債にならないよう、以下の運用ルールを厳守してください。

### 1. 新規例外の追加手順
既存のカテゴリに該当しない、あるいは新しい判断が必要なハードコードを導入する場合は、以下の手順を踏んでください。
1.  妥当性の検証: その値が本当にトークン（ spacing, radius 等）で代用できないか再考する。
2.  本ドキュメントの更新: 理由と具体例を本ファイルに追記し、チームで合意を得る。
3.  ソースコードへの明記: ソースコード上で、本ファイルのどのカテゴリに該当するかコメントを残す。

    ```scss
    width: 18px; /* Exception: Geometric Harmony — トラック高さ(6px)に対する3:1比のサム直径 */
    width: 1em;  /* Exception: Structural Logic — font-size に追従させる構造的寸法 */
    ```

### 2. 暫定的ハードコードの扱い (`// TODO: tokenization`)
適切なトークンが見つからない、あるいはトークンセットの拡張が必要だが、開発スピードを優先して一時的にハードコードする場合は、例外として認められません。
- 必ず該当箇所に `// TODO: tokenization` コメントを残してください。
- コメントのない未承認のハードコードはビルドエラーまたはリジェクトの対象となります。

### 3. 機械チェック（`npm run audit:hardcoded`）
`scripts/check-hardcoded-values.js`（`npm run audit:all` にも含まれます）が以下を検査します。
- カラーコード: 1件でも検出したら即エラー（下記「禁止事項」参照）。
- px 直書き: 同一行に `Exception:` / `TODO: tokenization` コメントがないものをカウントし、スクリプト内の `PX_BASELINE` を超えたらエラーになります（ラチェット方式）。既存分を注記・トークン化して数を減らしたら、`PX_BASELINE` を実測値まで下げてコミットしてください。増やす方向の変更は認められません。
- `var(--x, 4px)` のようなトークン/変数参照のフォールバック値は検査対象外です（参照が主体の防御的既定値のため）。

### 4. 禁止事項
- カラーコード (#hex, rgb, rgba) のハードコード: これらは例外なくデザイントークンを使用してください。テーマ切り替え（ダークモード）に致命的な影響を与えます。
  - コンポーネント固有の固定色（例: Terminal の macOS トラフィックライト）も `tokens/color/semantic.json` にトークンとして定義してください（`terminal-traffic-red/yellow/green` が前例です）。
  - 唯一の例外: `mask-image` 等のアルファチャンネルのみが意味を持つ色停止（`rgb(0 0 0)` 等、画面上の色として描画されない値）。この場合も同一行に `// Exception: mask 用アルファ色停止` コメントが必須です（例: Tabs の `--_mask-opaque`）。
- 意味不明なマジックナンバー: `3.1415px` のような値は、必ずその根拠となった計算式や背景をコメントで残してください。
