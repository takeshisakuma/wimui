# `vrt-diff-metrics.json` の作り方

`vrt-diff-classify.js` の回帰テスト用に、**実際のベースライン更新から測った数値**を
固定してある。画像そのものは置かない（3 組で 303 枚・数十 MB になるため）。

## 中身

3 組とも「どれが実変更か」が独立に分かっているベースライン更新である。**1 組だけ
だと閾値をそこに合わせてしまう**ので、性格の違う 3 組を入れている。

| 組 | コミット範囲 | 実変更 | 性格 |
|---|---|--:|---|
| #257 | `c4db850ec..5a88e93d8` | 18 / 90 | アイコンの**字形差し替え**（T81 の起票元） |
| #277 | `a28ae1552..c1e3f510d` | 2 / 103 | 列幅が上限として効き、**セルの中身が動く** |
| #278 | `9e4afcff5..1f96c3f84` | 28 / 110 | Alert のアイコンが 1 行目に揃い、**要素が動く** |

`real: true` は「そのコミットが意図した変更に含まれるか」で、コミットの diff と
PR の内容から決めている。#278 の `wholesale-account--business-invalid` のように
**画面の中に Alert があるだけのストーリー**も実変更に含まれる（最初はノイズと
誤ってラベルを付けており、閾値ではなくラベルのほうが誤りだった）。

## 測り直す

各画素について前後の差を取り、`shift`（符号付き平均の移動量）/ `area`（差分画素の
割合）/ `strongPct`（**いずれかのチャンネルが 64 以上動いた画素の割合**）を出す。
計算そのものは `vrt-color-shift-report.js` の `measure()` と同じで、`--base` /
`--head` にコミットを渡せばそのまま得られる:

```bash
node scripts/vrt-color-shift-report.js --base c4db850ec --head 5a88e93d8
```

新しい組を足すときは、**その組で `real` をどう決めたかを上の表に書くこと。**
ラベルの根拠が残っていないデータは、閾値を動かすときに使えない。
